# GaitRAG — Project Brief for Claude Code

## 1. What this project is

GaitRAG is an evidence-grounded gait analysis assistant. A user uploads a walking recording (wearable insole IMU + pressure CSV). The system:

1. Runs a trained Random Forest model to classify walking speed (slow / normal / fast).
2. Extracts interpretable gait features (cadence, stride time, stride variability, stance/swing ratio, left–right pressure asymmetry).
3. Uses those features to build a retrieval query over a curated corpus of biomechanics / gait research papers.
4. Generates an explanation that compares the user's values to published norms, where **every claim is cited** (paper, page, table) — or states "insufficient evidence" when the sources don't support an answer.

**Positioning:** research and education tool for researchers and physiotherapy students. **Not a diagnostic tool.** A disclaimer must appear in the UI, API responses, and README.

## 3. Data & legal constraints (important)

- **Sensor dataset:** the real gait dataset (276 trials, 23 participants, FSR pressure sensors + 4 IMUs + depth camera) was co-built during my research internship at NIT Bhopal (MANIT). **Do not commit any real participant data to the repo.** The public repo and live demo must use **synthetic sample recordings** generated by a script (`scripts/make_synthetic_gait.py`) that mimic the real CSV schema. I will check with my supervisor before using real data anywhere public.
- **Papers:** the public repo and demo may only include **open-access papers** whose licence allows redistribution (e.g. CC-BY). Store the paper list with DOI, title, licence and source URL in `data/papers/manifest.csv`. PDFs themselves go in `data/papers/pdfs/` which is git-ignored; a script downloads them from the manifest.
- **Privacy:** uploaded recordings are processed in memory and not stored server-side in the demo.

## 4. Tech stack

| Layer | Choice | Notes |
|---|---|---|
| Frontend | React + Vite + TypeScript, Tailwind CSS, Recharts | Dashboard: upload, sensor plots, feature cards, answer panel with clickable citations |
| Backend | Python 3.11, FastAPI, Pydantic | Serves both ML model and RAG pipeline |
| ML | scikit-learn (Random Forest), NumPy, pandas, SciPy | Statistical + FFT features, subject-wise z-score normalization |
| RAG framework | LlamaIndex | Good PDF/table handling |
| PDF parsing | PyMuPDF for text; `pdfplumber` or Camelot for tables | Tables extracted to structured rows |
| Vector DB | PostgreSQL + pgvector | Embeddings + paper metadata + extracted norm tables in one DB |
| Keyword search | BM25 (`rank_bm25` or Postgres full-text search) | For hybrid retrieval |
| Embeddings | `BAAI/bge-small-en-v1.5` (HuggingFace) by default | Configurable |
| Reranker | `BAAI/bge-reranker-base` cross-encoder | Configurable, can be toggled off for ablation |
| LLM | Pluggable: OpenAI (e.g. `gpt-4o-mini`) **or** an open HuggingFace model (e.g. Mistral/Llama via an inference API) | Selected via env var; same prompt interface |
| Evaluation | RAGAS + custom scripts | See Section 7 |
| Infra | Docker + docker-compose, GitHub Actions CI | Deploy to Render/Railway (or AWS) |

## 7. Evaluation plan

The eval set is **written by me** (50–100 questions), stored as JSONL:

```json
{"id": "q001", "question": "What is the typical stride time variability in healthy adults?", "gold_paper_ids": ["P012", "P045"], "gold_answer": "...", "type": "norm_lookup"}
```

Question types: `norm_lookup`, `method_comparison`, `feature_interpretation`, `unanswerable` (for testing insufficient-evidence mode).

**Metrics to report:**
- Retrieval: Recall@5, Recall@10, MRR
- Generation: RAGAS faithfulness, answer relevancy, context precision
- Citation accuracy: % of cited sources that actually contain the supporting claim (manual check on a sample)
- Abstention: precision/recall of "insufficient evidence" on `unanswerable` questions
- Latency: p50 and p95 end-to-end for `/ask` and `/analyze`

**Ablations (the key result table):**
1. Vector-only
2. BM25-only
3. Hybrid (RRF)
4. Hybrid + reranker
5. Hybrid + reranker + norms-table lookup

Also compare OpenAI vs open HuggingFace LLM on faithfulness and latency. Results are written to `eval/results/` as Markdown + CSV and summarised in the README.

## 8. Milestones (do these in order)

**M0 — Setup**
Repo skeleton, docker-compose (Postgres + pgvector, backend, frontend), `.env.example`, pre-commit (ruff, black, prettier), basic CI running lint + tests, `/health` endpoint.

**M1 — Synthetic data + ML model**
`make_synthetic_gait.py` producing CSVs matching the schema below. Feature extraction (statistical + FFT features, cadence, stride time/variability, stance/swing, L–R pressure asymmetry), subject-wise z-score normalization, Random Forest training script, `/analyze` endpoint returning prediction + features. Tests for feature extraction.

CSV schema (to be confirmed by me against the real data):
`timestamp_ms, subject_id, trial_id, fsr_l_heel, fsr_l_meta, fsr_l_toe, fsr_r_heel, fsr_r_meta, fsr_r_toe, imu{1..4}_ax, _ay, _az, _gx, _gy, _gz`

**M2 — Paper ingestion**
`download_papers.py` from manifest, PDF text parsing, chunking (propose a strategy and justify it), embeddings into pgvector, metadata storage. Table extraction into a structured `norms` table (paper_id, page, table_no, metric, population, value/range, units).

**M3 — Retrieval**
BM25 index, vector search, Reciprocal Rank Fusion, cross-encoder reranker, each toggleable via config for ablations. Query builder that turns extracted features into a retrieval query.

**M4 — Generation**
Prompting with mandatory inline citations `[P012, p.4, Table 2]`, norms lookup injected as structured context, insufficient-evidence mode, pluggable LLM provider, `/ask` endpoint. Response always includes disclaimer.

**M5 — Frontend**
Upload page, sensor signal plots, feature cards with "vs published norm" indicators, answer panel with clickable citations (opens source details), follow-up question box, visible disclaimer, one-click "try with sample recording".

**M6 — Evaluation**
Eval scripts from Section 7, ablation runs, results tables. (I write `questions.jsonl` before this milestone.)

**M7 — Deployment & polish**
Production Dockerfiles, GitHub Actions (lint, test, build, deploy), live deployment, README with architecture diagram, setup instructions, demo GIF, results table, limitations section, disclaimer.
